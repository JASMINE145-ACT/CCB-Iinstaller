# Migrating `agent-eval-plugin` to another repo

This plugin's code is self-contained, but *using* it in a repo (this one, or a
new one) touches a few files outside this directory. This doc lists what to
bring along, what's optional, and what to leave behind.

## 1. This directory — always required

Everything under `agent-eval-plugin/` is the engine and is self-contained:

- `core/`, `adapters/`, `adapter-sdk/`, `graders/`, `hosts/`, `report-templates/`, `schemas/`, `scripts/`, `skills/`, `test/`
- `package.json` (`npm test` → `node --test`)
- Host manifests: `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `.cursor-plugin/plugin.json`

Copying just this folder gives you a working engine, but no Cases/Suites to
run yet — see §2.

## 2. Repo-root `.agent-eval/` — required for actual use

This is the **data** side: Cases, Suites, run output, and project config —
not part of the plugin package itself.

```
.agent-eval/
  config.json   # default_adapter, default_suite, storage layout, privacy flags
  cases/        # eval.case/v1 JSON files
  suites/       # suite definitions (which cases, in what mode)
  runs/         # per-run output (gitignored)
```

`config.json` currently points `default_adapter` at `ccb-acp` (this repo's
runtime adapter) and `default_suite` at `smoke` — update both if the new repo
targets a different Agent runtime.

Gitignored (regenerated by running evals, do not need to migrate):
```
.agent-eval/runs/
.agent-eval/reports/private/
.agent-eval/artifacts/
```

## 3. `.agents/skills/agent-eval/SKILL.md` — optional, host-discovery only

A thin loader (~15 lines) for AI hosts that scan `.agents/skills/` for
skills. It contains no logic of its own — it just points at:

- `../../../agent-eval-plugin/skills/agent-eval/SKILL.md` (the real skill)
- `../../../agent-eval-plugin/scripts/agent-eval.mjs` (the CLI entrypoint)

Only needed if the new repo's host tooling discovers skills via
`.agents/skills/` instead of (or in addition to) the plugin manifests in §1.
If you copy it, fix the relative path depth if the plugin doesn't land at the
new repo's root.

## 4. Host permission rules — regenerate, don't copy verbatim

`.codex/rules/default.rules` (and equivalent Claude Code / Cursor permission
config) has `prefix_rule` allow-entries for commands like:

```
node agent-eval-plugin\scripts\agent-eval.mjs ...
npm test --prefix agent-eval-plugin
```

These are host-specific and reference this repo's paths — recreate the
equivalent allowlist entries in the target repo rather than copying the file.

## 5. Do NOT bring along — unrelated systems

- **`eval/` (repo root)** — a separate, older regression harness for
  CCB-Wanding agent routing / MCP tool choice. Different purpose, different
  code, no relation to `agent-eval-plugin`. Don't confuse the two or merge
  them during migration.
- **`Agent eval system/`** — pre-implementation PRD + design doc. History
  only; superseded by this plugin's own README and skill docs.
- **`.trellis/spec/agent-eval/`, `.trellis/tasks/07-15-agent-eval-plugin-harness/`,
  `docs/superpowers/plans/2026-07-15-agent-eval-plugin-harness.md`** — this
  repo's planning/spec/task archive for how the plugin was built. Useful as
  background reading, not a runtime dependency.

## Minimal migration checklist

1. Copy `agent-eval-plugin/` to the new repo.
2. Copy `.agent-eval/config.json`, `.agent-eval/cases/`, `.agent-eval/suites/`
   to the new repo's root; update `default_adapter` if targeting a different
   runtime adapter than `ccb-acp`.
3. Run `npm test --prefix agent-eval-plugin` to confirm the engine works
   standalone.
4. If the target host scans `.agents/skills/`, copy/recreate the loader from §3.
5. Recreate permission-rule allowlist entries for the new repo's paths.
6. Skip `eval/`, `Agent eval system/`, and the `.trellis/` planning archive.
