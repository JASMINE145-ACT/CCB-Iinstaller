## 1) 选型总原则（硬约束）

按下面顺序决策，前一层不满足时不得进入后一层：

1. **品类语义一致性（最高优先）**
2. **关键规格一致性（必须）**
3. **次级属性比较（压力等级/S 系列/品牌）**
4. **来源加权（仅作 tie-breaker，不是一票否决）**

### 1.1 来源规则

- 来源只在"语义与规格都接近"时生效；
- 当来源优先候选与用户语义冲突时（如用户要"热水管"，候选是"冷给水"），**必须降权或排除**。

### 1.2 典型纠偏（热水管案例）

用户：`PPR热水管3/4寸`
如果候选中"字段匹配"有 `热给水直管 dn25 (3/4")`，而"历史报价"是 `冷给水直管 dn25 (3/4")`，应优先热给水直管。
**结论：语义一致性（热/冷）高于来源优先级。**

## 2) 强约束（弯头角度 · 主径×副径）

### 2.1 弯头角度

- 半弯 => 45°弯头（不得与"弯头"泛化混同）
- 全弯 / 直角弯 => 90°弯头
- 未写"半弯"的"弯头"默认按 90°优先

### 2.2 主径×副径（A*B / A×B / AB）

- 形如 `32*20` / `32×20` / `3220`：A 为主径（dn），B 为副径（英寸侧）
- B 与英寸映射：15/16/20 => 1/2"；25 => 3/4"；32 => 1"；40 => 1-1/4"；50 => 1-1/2"
- A 与 dn 映射：20=>dn20，25=>dn25，32=>dn32，40=>dn40
- 示例：`32*20内丝三通` => 优先 `dn32x1/2"`，不选 `dn32x3/4"`
- 若仅单数值（如 `32弯头`）且无副径，不推断副径

## 3) 场景型业务规则

1. 三角阀 != 角阀；仅有角阀候选时判无匹配
2. 软管：库内无软管类产品，询价含"软管"返回无匹配
3. 规格精确匹配优先：dn25 不选 dn20
4. 等径三通优先于异径三通（除非用户明确要异径）
5. `50cm` 表示长度，不得误判为 dn50 管径
6. 电工套管场景：
   - conduit / 电线管 => PVC 电线管(B管)
   - socket => 管直通(套筒)
   - klem / 马鞍卡 => 管夹(U型)
   - tdust 4 cabang => 管四通圆接线盒(带盖)
   - 热熔器 => 焊接机
7. Elbow drat = 丝扣弯头 / 螺纹弯头（AW 给水 Faucet Elbow `80100248xx` 系列）
   - 来源：报价专家会话确认，2026-07-07（PT. JINSE 7.1 报价单行 10 drat 漏召复盘）

## 4) 品类默认

### 4.1 【PVC-U 排水 / 默认口径】（原 §4.1+§4.2+§4.6+§4.7；CONF-001/002 已解除）

#### 4.1.1 口径分层（直管 vs 管件）

| 用户输入 | 默认走 | 颜色 | 备注 |
|---------|--------|------|------|
| `PVC直管`/`PVC pipe`/`PVC管`（**直管**语义） | **D 排水系列** | 灰色（JIS 日标） | DN 允许降级替换：DN110→DN100(4")、DN75→DN65(2-1/2")；编码例 DN100=`8020012382`、DN65=`8020012380` |
| `PVC直通`/`直接`/`弯头`/`三通`/`管件`（**管件**语义） | **A 系列国标** | 白色国标 | 数字 50/110/150 → dn50/dn110/**dn160**；管 `802001xxxx` / 管件白 `8020020xxx` |
| `PVC给水`/`AW`/`water supply`/`pressure pipe` | AW 给水系列 | 灰色 DN20+ | 用户已明确给水，**不走默认** |
| `PVC排水`/`排污`/`drain`/`drainage` | D 排水系列 | 灰色 | 直管走 D；管件仍走 A（除非用户说「D 灰色排水管件」） |
| `PVC电线管`/`conduit`/`B管`/`穿线管` | PVC 电线管 | 白色 | 见 §4.5 conduit 体系，不与给水/排水混用 |

#### 4.1.2 直管 vs 管件的边界识别

1. 关键词带**具体管件名**（直通/直接/弯头/三通/变径/管帽/管夹/堵头/接头/套筒/异径接头/线盒/接线盒）→ 走 A 系列管件；
2. 关键词带「**直管/管/pipe**」且无管件名 → 走 D 排水直管；
3. 同一条询价同时出现管材 + 管件 → 直管按 D、管件按 A，**不互相替代**；
4. 仅写「PVC」无任何品类词 → 追问，不默认。

#### 4.1.3 三通分流（A 系列国标白色管件体系下）

| 用户输入 | 默认走 |
|---------|--------|
| `三通`（无「斜」字） | **A 系列白色顺水三通**：**短型 DT > 长型 LT**；DN150\*100\*150 锁定短型 DT（`8020022847`，前缀 8020022xxx）；**禁止**混推 45° 斜三通（`8020022637`） |
| `斜三通`/`45°`/`Y Branch`/`Y三通` | **A 系列白色 45° 斜三通**；屏闭 DT/LT 顺水三通 |
| AW 给水三通 / PPR 三通 / PE 三通 | 走各自体系（见 §4.2、§4.3） |

- 来源：报价专家会话确认，2026-07-06；人类报价单「谢总 营地材料7.6报价单」
- 输出：区分「三通（无斜字）」vs「斜三通/Y三通」；关键词判定后**禁止混合推荐**；附选型依据。

#### 4.1.4 数字口径映射（统一）

| 用户写 | 解析为 |
|--------|--------|
| `50` / `2"` | dn50 / DN50(2") |
| `110` / `4"` | dn110（A 系列）/ DN100(4")（D 系列） |
| `75` / `2-1/2"` | dn75（A 系列）/ DN65(2-1/2")（D 系列） |
| `150` | **dn160**（A 系列国标）/ DN150（D 系列日标） |

> 原 CONF-002 已解除：A 系列 `150 → dn160` 为固定写法，**不再追问**。

#### 4.1.5 A 系列管件关键词与易混点

- "150 直通" → keywords = "PVC-U 排水 dn160 直通"
- "150 管夹" → keywords = "dn160 管卡"（不说「长螺丝」则选 8020020182）
- "150 变 110 直通" → keywords = "dn160 异径直通" 或 "大小头 dn160x110"（不是普通直通）
- 异径直通 ≠ 普通直通：必须走「大小头」编码（8020020049 类）
- 管夹长螺丝款 ≠ 标准款：默认 8020020182
- 主管 A 系列 ≠ 主管 D 系列：默认 8020010018（dn110）/ 8020010044（dn160）
  - 来源：报价专家会话确认，2026-06-29

#### 4.1.6 必须追问的场景（仅 3 类）

1. 同一条询价同时出现给水 + 排水语义；
2. 数字口径与 DN 替换冲突（如 DN75 只有 dn65 / dn80 候选）；
3. 仅写「PVC」无任何品类词（按 4.1.2 第 4 条）。

### 4.2 PPR 冷热水与管材/管件选择

- 用户写 `热水`、`hot water` 时，优先热给水/热水管；不要因为历史报价来源优先而选冷给水。
- 用户写 `冷水`、`cold water` 时，优先冷给水/冷水管。
- 用户只写 `PPR管` 且未说明冷热时，可以保留候选并询问冷热/压力等级；不要主动编造。
- `弯头`、`三通`、`直接/直通`、`变径`、`截止阀`、`管帽/堵头` 是不同品类；候选里有明确品类时，不要跨品类替代。
- 用户只写 `弯头` 且未写角度时，默认 90°弯头优先；写 `半弯` 时优先 45°弯头。

### 4.3 PE / HDPE 默认与电熔

- 用户只写 `PE管`、`HDPE管`、`PE给水管` 时，默认按普通给水管/对接体系理解，不主动选择电熔管件。
- 用户明确写 `电熔`、`electrofusion` 时，才选择电熔管件。
- 用户明确写 `对接`、`butt welding` 时，排除电熔候选。
- PE/HDPE 压力等级差异明显时（如 PN10、PN12.5、PN16、0.6MPa、1.0MPa），若用户未给压力且候选接近，必须追问。

### 4.4 胶水、辅材、非管件

- `胶水`、`胶粘剂`、`cement`、`glue` 只能在胶水/胶粘剂类候选中选择，不要选 DN400、400mm 等管材。
- `热熔器` 是工具/焊接机，不是 PPR 热水管或管件。
- `软管` 当前按无直接匹配处理；如用户接受替代，再由用户明确确认。
- **PVC 胶水 400g 默认选 ISARPLAS**（编码 `GPR-LL02L00004`）；同规格 ASOKA（`GPR-LL02L21002`）仅作备选。
  - 来源：报价专家会话确认，2026-07-06；人类报价单「谢总 营地材料7.6报价单」

### 4.5 PVC conduit 与 AW 给水体系区分

- 同一行/同一组询价里若同时出现 **「PVC线管/PVC conduit」** 与 **「PVC直接/套筒」**，直接头/套筒必须走 **PVC 电工套管配件（同 conduit 体系、白色）**，不得跳到 AW 给水直通或 D 排水直通。
- **PVC conduit = 通电线**（电线管 / 穿线管），不是给水管。
- **AW 给水管 = 通水**（给水系列，灰色 DN20 等），与 conduit 是完全不同的两个体系，不能混用。
- 常见配套编码：
  - PVC 电线管(B管) dn20 → 8030050068
  - PVC 电工套管配件 直通(套筒) Φ20 → 8030020288（与 8030050068 配套）
- 单独出现「PVC直接 20」无「线管」上下文时，仍优先 conduit 套筒（8030020288），其次 AW 给水直通（8010024551）；只有用户明确说「给水直通/进水直接」才走 AW。
  - 来源：老杨（万鼎国际印尼）业务纠偏，2026-07-06；嘉诚 2026-07-06 报价会话确认

## 5) 规格与单位

- `dn/de/od/d + 数字`、`数字mm`、英寸规格是管径；`cm` 通常是长度，不得当作 DN。
- `PN`、`MPa` 是压力等级，不得当作管径。例如 `PN20` 不是 `DN20`。
- `4M/根`、`4m/pcs` 是单根长度，只在用户明确要求长度时作为筛选条件。
- 候选只有相邻规格（如 DN75 与 DN65、DN110 与 DN100）时，除非本知识库已有明确默认，否则应询问用户是否接受替代。

## 6) 来源优先级边界

- `共同`、`历史报价`、`字段匹配`只能作为最后 tie-breaker。
- 如果历史报价候选与用户品类/用途/冷热/规格冲突，即使来源更高，也要降权或排除。
- 如果字段匹配候选在语义和规格上明显更准确，应优先字段匹配。

## 8) 交互与陈述纪律（硬约束）

### 8.1 语言

- **所有面向用户的回复必须使用中文**（简体），包括询问、说明、汇总、错误提示。
- 物料编码、规格代号（如 dn50、PE、1.0MPa）、单位、价格、英文品牌名（LESSO、RUCIKA）等专有名词保留原文。
- 印尼/英文表单字段（如 Nama Penawaran、Product number）也保留原文，不翻译。
- 用户使用其他语言（如英文、印尼文）提问时，仍用中文回复，并在必要时附上原文引用。

### 8.2 拿不准必须询问

- **多选拿不准时必须主动询问用户**，不要硬选、不要沉默、不要编造。
  - 典型场景：PVC 仅 §4.1.6 三类必须追问（给水+排水同条 / DN 替换冲突 / 仅写「PVC」）；**直管 D vs 管件 A 已定，不再因 CONF-001 追问**
  - 典型场景：候选中「压强/系列/材质」无法从用户描述中确定（非上述已定默认）
  - 典型场景：DN 替换冲突（§4.1.6 第 2 类；库内仅相邻规格且无默认）
  - 典型场景：库内无直接匹配（PP管无货、PP vs PPR 替代）
- **一律在 assistant 正文中追问**，**禁止** `AskUserQuestion` 工具。
- 询问时**一次只问 1~3 个聚焦问题**，每题 2~4 个清晰选项（A/B/C）+ 推荐项；可写「请按 `1A 2C` 格式一次回复」。
- **查后多候选**：在正文列出 markdown 表（序号、编码、名称、单价），请用户回复编码或序号。
- 若用户已经给出过明确选择（如上一轮已确定走 D 排水），后续同类型询价**直接沿用**，不必每次再问。
- 同一会话中已确认的规则（客户等级、是否含税、DN 替换策略等）应持续生效。

### 8.3 推断与事实分离

- **禁止**把行业惯例、个人经验、模型推断当事实直接陈述。
- 给出映射表、口径对照、价档解释前，必须先回答：「这条信息是从哪个具体来源（知识库章节 / MCP 返回字段 / 文件路径）来的？」
- 如果来源是经验或推断，必须显式标注：「⚠️ 推断，尚未在知识库 / 价库明文化」。
- 阻塞性结论（编码、单价、库存判定）必须有可追溯依据。

### 8.4 引用原文必须贴出

- 任何引用知识库规则、§章节时，**必须**在同一条回复中贴出原文片段（含章节号 / 文件路径），不能只说「根据知识库 §X」。
- 例（正确）：贴出 §2.2 主径×副径映射原文后再下结论。
- 例（错误，禁止）：「根据知识库 §3，DN20 对应 1/2」——没贴原文。

### 8.5 优先级

§8 行为纪律优先级高于业务默认；与 §1 选型总原则并列适用，不冲突。
适用范围：查价回复、报价单说明、`learn-by-data` 复盘、共享规则预览、用户纠偏解释。
