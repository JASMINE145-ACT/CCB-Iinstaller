# PRD：AI 客户线索搜索工具（v2 精简版）

## 1. 项目背景

化工销售开发客户时，主要靠人工在天眼查、百度、行业网站搜索企业信息，再手动复制到 WPS 表格。问题：搜索关键词不系统、信息分散、重复录入、筛选标准不一、跟进困难。

本项目要做一个 AI 辅助工具：业务输入产品名 + 重点方向，系统自动生成搜索关键词，从合规数据源获取企业信息，按匹配度整理成 WPS 客户线索表。

## 2. 目标用户

销售、业务开发、市场调研人员。

典型场景：销售想开发"52号氯化石蜡"的下游客户，但不知道"润滑脂、切削液、极压添加剂"这些下游词；不知道江苏、浙江哪些企业是潜在采购方；不知道这些企业目前的跟进状态。

## 3. 核心痛点

1. 业务不懂下游行业词，搜不出精准客户。
2. 关键词和经营范围匹配需要专业知识，新人无法上手。
3. 客户信息复制整理耗时，容易漏字段。
4. 销售跟进无统一标准，线索没有评分沉淀。

## 4. 产品目标

1. 产品名 → 自动生成下游行业关键词。
2. 关键词 → 在合规数据源查询企业基础信息。
3. 企业信息 → AI 判断匹配度（高 / 中 / 低）。
4. 匹配结果 → 导出 WPS 客户线索表。
5. 销售 → 在表上手动标记跟进状态（待联系 / 已联系 / 有效 / 无效 / 报价中 / 成交）。

## 5. MVP 范围（最小可用版本，1 周交付）

只做 4 步，砍掉一切延后需求：

| 步骤 | 内容 | 实现方式 | 工时 |
|---|---|---|---|
| 1 | 输入产品名 + 重点方向 | Web 表单 | 0.5 天 |
| 2 | AI 生成 10-20 个搜索关键词 | LLM API | 1 天 |
| 3 | 业务从天眼查导出 CSV 上传 | 文件上传 | 1 天 |
| 4 | AI 清洗 + 三档匹配 + 导出 .xlsx | Python + OpenPyXL | 2 天 |

**Step 3 是 MVP 和企业版的分水岭**：MVP 用人工导数据，企业版用 API 自动查。

## 6. 不做的功能（MVP 不做）

- 自动拨号 / 自动群发邮件
- CRM 全流程
- 绕过天眼查的爬虫
- 复杂权限系统 / 团队协作
- 100 分精细评分（用三档）
- 长期客户数据库（先做单次任务）
- 关键词的"大范围 / 精准 / 匹配"三类分桶（LLM 一次输出即可）

## 7. 输入示例

```
产品：52号氯化石蜡
重点方向：润滑油、润滑脂
地区：全国，优先华东、华南
客户类型：生产型企业、贸易商
排除：注销、吊销、严重失信
```

## 8. 关键词生成（AI 责任）

输入产品名 + 重点方向后，LLM 一次输出：

- **搜索关键词**（用于天眼查查询）：润滑油、润滑脂、切削液、极压添加剂、防锈油、液压油、齿轮油、特种润滑脂
- **匹配关键词**（用于判断企业是否相关）：润滑油生产、润滑脂生产、金属加工液生产、专用化学产品制造、石油制品销售

LLM 自己决定哪些词用于"搜"、哪些词用于"匹配"，**不预设分类**。业务方对结果不满意可手动改。

## 9. 查询流程

```mermaid
flowchart LR
    A[业务输入产品名] --> B[LLM 生成关键词]
    B --> C[业务确认/调整关键词]
    C --> D[业务从天眼查导 CSV]
    D --> E[上传 CSV]
    E --> F[LLM 清洗 + 三档匹配]
    F --> G[导出 .xlsx]
    G --> H[销售标记跟进状态]
```

## 10. 三档匹配规则

MVP 不做 100 分制，只分三档：

| 等级 | 判定条件（任一） | 颜色标记 |
|---|---|---|
| 高 | 经营范围直接出现"XX 生产、XX 制造" | 绿色 |
| 中 | 经营范围出现"XX 销售、化工产品" | 黄色 |
| 低 | 经营范围模糊相关或需人工确认 | 灰色 |

导出 .xlsx 时按等级分组、冻结表头、列加筛选、A 列高亮。

## 11. WPS 表格字段

| 字段 | 来源 | 备注 |
|---|---|---|
| 序号 | 自动生成 | 1, 2, 3... |
| 企业名称 | 天眼查 | 必填 |
| 所在省市 | 天眼查 | 必填 |
| 所属行业 | AI 推断 | 标签 |
| 经营状态 | 天眼查 | 存续 / 在业 / 注销 / 吊销 |
| 注册资本 | 天眼查 | 单位万元 |
| 成立时间 | 天眼查 | YYYY-MM-DD |
| 经营范围摘要 | 天眼查 + AI 截取 | 截取前 100 字 |
| 匹配关键词 | AI 提取 | 命中词列表 |
| 匹配等级 | AI 判断 | 高 / 中 / 低 |
| 推荐理由 | AI 生成 | 1-2 句话 |
| 联系电话 | 天眼查 | 可空 |
| 官网 / 邮箱 | 天眼查 | 可空 |
| 数据来源 | 自动 | "天眼查 + AI" |
| 跟进状态 | 销售手动 | 待联系 / 已联系 / 有效 / 无效 / 报价中 / 成交 |
| 备注 | 销售手动 | 自由文本 |

## 12. 真正的难点（必须解决）

### 12.1 天眼查数据源

**这是项目唯一卡点**。三种方案，从易到难：

| 方案 | 成本 | 时效 | 风险 |
|---|---|---|---|
| 销售每天手动导 CSV | 人力成本 | T+1 | 人工漏导 |
| 销售申请会员批量导出 | 会员年费约 ¥3000-10000 | T+1 | 数据延迟 |
| 申请天眼查开放平台 API | 按次计费，约 ¥0.5-2/次 | 实时 | 需企业资质 + 审核 7-15 天 |

**MVP 强制使用方案 1 或 2**。负责人：张宇；时间窗：上线前必须确定。

### 12.2 LLM 调用成本

每次匹配一条企业记录需一次 LLM 调用。估算：

- 单次查询约返回 200-500 条企业
- 每条约 1k-2k token
- 单次查询成本约 ¥2-8（按 DeepSeek-V3 计价）

**应对**：匹配任务用 DeepSeek-V3 或本地模型，不用 Claude / GPT-4。月预算控制在 ¥500 内。匹配结果带"人工可覆盖"标记。

### 12.3 企业去重

跨关键词搜索可能命中同一公司。MVP 规则：

- 主键：企业名称 + 所在城市（粗去重，90% 命中率）
- 二次过滤：统一社会信用代码（可选，天眼查导出的字段不总是有）
- 重复记录保留最高匹配等级

## 13. 成功指标（MVP 上线 4 周后验收）

- 单次任务从输入到导出 .xlsx ≤ 5 分钟
- 销售每天能完成 ≥ 3 次任务（即 ≥ 3 份线索表）
- 输出线索中"高"匹配客户占比 ≥ 20%
- 销售对 AI 评分的人工修正率 ≤ 30%
- LLM 月度成本 ≤ ¥500

## 14. 技术栈

MVP 阶段：

- **后端**：Python + FastAPI（轻量，1 个文件起服务）
- **前端**：Streamlit（最快出 Demo，2 小时搭好）
- **LLM**：DeepSeek-V3 API（性价比最高）
- **数据处理**：Pandas + OpenPyXL
- **文件存储**：本地文件系统（MVP 不上数据库）
