# Progress 2026-06-29

## Repeated symptom

Inventory code `8020020755` sometimes returned a completed MCP payload and was
then followed by `[Tool use interrupted]`; a later identical request succeeded.

## Second root cause

The actual SDK transcript contained a valid `tool_use` and matching
`tool_result`, followed by a separate assistant message containing the literal
placeholder. Aioncore logs showed a normal completed update and `end_turn`, with
no cancellation, timeout, transport failure, org 401, or inventory error.

`ensureToolResultPairing()` in `D:\claude-code-B\src\utils\messages.ts` removed
a repeated ordinary `tool_use`, but when that left an empty assistant message it
unconditionally inserted `[Tool use interrupted]`. A successful duplicate
stream event was therefore misclassified as an interrupted operation.

## Repair

Duplicate-only ordinary tool-use messages are now dropped. Genuine orphan
server/MCP tool-use messages retain the interruption placeholder.

Regression:
`drops duplicate-only tool_use message after a completed result instead of emitting interrupted placeholder`.
