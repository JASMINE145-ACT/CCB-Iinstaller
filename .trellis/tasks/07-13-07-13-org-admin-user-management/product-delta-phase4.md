## 四个问题的结论

### 1. 「组织用户」谁能管？

**只有「系统管理员」**（数据库字段 `is_admin=1`）。

| 身份 | 能不能管组织用户 | 能不能看到入口 |
|------|------------------|----------------|
| 系统管理员（现在基本是账号 `admin`） | 能 | 能 |
| 普通经理（任务派工用的经理，不是系统管理员） | 不能 | 不能 |
| 普通员工 | 不能 | 不能 |

注意：**任务里的「经理」≠ 系统管理员**。日常提拔第二个系统管理员，要改库里的管理员标记；第四阶段可以在设置里勾选，但仍只有现有系统管理员能操作。

### 2. 有的员工要能改价格库 / 供应商

今天价格库「写入」（导入、发布）靠服务器环境变量白名单，通常只有 `admin`，**没法按员工细粒度授权**。

增补：**业务权限位**（和「经理/员工」「系统管理员」分开）：

| 权限位 | 含义 |
|--------|------|
| 价格库写入 | 可改草稿、导入、发布价格库 |
| 供应商写入 | 可增删改供应商 |

- **读**：登录用户默认可看（与现在一致）
- **写**：有对应权限位 **或** 系统管理员
- 由系统管理员在「设置 → 组织」里给员工勾选
- 过渡期：环境变量白名单与权限位 **同时有效**，以后以权限位为准

### 3. 放到设置更合适

**采纳。** 从主侧栏挪到 **设置 → 组织**：

| 建议页面 | 内容 |
|----------|------|
| 设置 → 组织 → 用户 | 现有组织用户列表 / 新建 / 编辑 |
| 设置 → 组织 → 架构 | 上下级关系图 |

主侧栏「组织用户」入口 **去掉**；只有系统管理员才在设置里看到「组织」。

### 4. 类似 Rudder 的上下级架构图

**采纳（样子借鉴，数据用现有字段）。**

- 数据：已有「直属上级」字段 + 姓名 / 岗位 / 部门
- 界面：自上而下卡片树（头像、姓名、岗位、连线，可缩放）
- **本阶段不做**：整包导入导出组织、完整人事、独立「部门表」

树根：没有上级的人；多人并列；改上级默认在「用户」表单里改（架构图先只读浏览，不拖拽）。

## 契约一览（对内编号保留，对外少提）

| 编号 | 保护什么 |
|------|----------|
| 组织用户管理 | 只有系统管理员能建号 / 改身份 |
| 业务权限位 | 员工可单独拥有价格库 / 供应商写入权 |
| 设置入口 | 组织管理只在设置里，不在主侧栏 |
| 架构图界面 | 用「直属上级」画出上下级树 |
| 部门实体表 | **仍延期**（和汇报树不是一回事） |

## 有条件批准（2026-07-13）

第四阶段**可以做**，但 **4.2 必须同时满足**：

1. **写接口强制校验**：系统管理员 **或** 用户权限列表含对应项（价格库写入 / 供应商写入）；禁止只做界面勾选。  
2. **权限白名单**：只允许上述两个值入库；乱传字符串拒绝。  
3. **改上级防成环**：不能设为自己或自己的下级。

环境变量白名单仅过渡，与权限位 OR；最终以用户表权限位为准。
