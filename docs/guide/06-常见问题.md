# 常见问题与排错

---

## 启动问题

### Q: 双击 CCB 没反应，或一闪而过

**原因**：安装不完整，或 Bun / dist 文件被杀毒软件隔离。

**排查步骤**：
1. 右键 CCB 快捷方式 → 属性，确认目标路径为安装目录下的 `ccb.cmd`
2. 检查日志：
   ```
   %LOCALAPPDATA%\CCB\logs\
   ```
   找最新的 `launcher-xxxx.log` 查看报错
3. 用诊断模式启动，窗口会保持打开：
   ```
   开始菜单 → CCB → CCB 诊断
   ```

---

### Q: 红色报错：`Claude Code on Windows requires git-bash`

**原因**：Claude Code 找不到 Git Bash。

**解决**：
1. 确认你用的是 `ccb.cmd` 而不是直接运行 `claude` 命令
2. 卸载旧版 CCB，重新安装最新版（1.0.7+）
3. 如果仍然报错，手动设置环境变量后启动：
   ```powershell
   $env:CLAUDE_CODE_GIT_BASH_PATH = "$env:LOCALAPPDATA\Programs\CCB\vendor\git\bin\bash.exe"
   & "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
   ```

**注意**：不要在 PowerShell 中直接运行 `claude`，要用 `ccb.cmd`。

---

### Q: 报错 `CCB was unable to find CLAUDE_CODE_GIT_BASH_PATH path "..."`

**原因**：`CLAUDE_CODE_GIT_BASH_PATH` 设置了路径，但该路径下的 bash.exe 不存在。

**解决**：
1. 检查 bash.exe 是否存在：
   ```powershell
   Test-Path "$env:LOCALAPPDATA\Programs\CCB\vendor\git\bin\bash.exe"
   ```
2. 如果返回 `False`，说明 Git Bash 被杀毒软件删除，重新安装 CCB 并在杀毒软件中添加信任

---

### Q: 报错 `缺少 Bun 运行时` 或 `缺少 CCB 入口文件`

**原因**：安装不完整或文件被隔离。

**解决**：
1. 开始菜单 → CCB → 卸载 CCB
2. 在杀毒软件中添加 CCB 安装目录为信任区域
3. 重新安装

---

## 界面与显示问题

### Q: 界面是英文，不是中文

**原因**：可能安装的是官方 Claude Code 而非 CCB，或安装了旧版 CCB。

**验证**：
1. 确认通过 CCB 桌面快捷方式启动（不是通过 `claude` 命令）
2. 检查版本：
   ```
   %LOCALAPPDATA%\Programs\CCB\ccb.cmd --version
   ```
3. 如果是 1.0.6 以下，升级到 1.0.7

---

### Q: 界面出现乱码（如 `å¿«éåº¥`）

**原因**：终端编码不是 UTF-8，或汉化补丁出现 mojibake。

**解决**：
1. 确认使用 Windows Terminal（而非旧版 cmd.exe）
2. 在 Windows Terminal 设置中确认编码为 UTF-8
3. 如果通过开始菜单或 cmd 启动，让 ccb.cmd 自动重定向到 Windows Terminal

**已知问题**：在旧版 Windows 10（Build 18362 以下）的 ConHost 中可能出现乱码，升级 Windows 或使用 Windows Terminal 可解决。

---

### Q: 鼠标滚轮不能滚动

**原因**：终端鼠标追踪配置问题。

**主模式行为**（正确）：鼠标追踪 OFF → 终端原生滚轮接管。

如果滚轮仍不能用：
1. 确认使用的是 Windows Terminal，不是旧版 cmd
2. 在 Windows Terminal 中，确认没有禁用鼠标滚轮的设置
3. 如果在 VSCode 集成终端中运行，改用 Windows Terminal

---

### Q: 无法用鼠标选中文字

**正常行为**：主模式下鼠标可以直接拖动选字（终端原生选取）。

如果不能选：
- 检查是否在旧版 ConHost 中（不支持，换 Windows Terminal）
- 按住 Shift 再拖动，部分终端仅支持 Shift+鼠标选取

## MCP 问题

### Q: `/mcp` 显示 `exa failed`

1. 检查网络：`ping mcp.exa.ai`
2. 如果在公司网络，配置代理后重试
3. 重启 CCB

### Q: `/mcp` 什么都不显示，或没有 exa 和 excel-mcp

`ccb-mcp.json` 可能未正确生成。手动重新生成：

```powershell
& "$env:LOCALAPPDATA\Programs\CCB\scripts\ensure-mcp-settings.ps1" `
  -InstallDir "$env:LOCALAPPDATA\Programs\CCB" `
  -ConfigDir "$env:LOCALAPPDATA\CCB\.claude"
```

然后重启 CCB。

## 安装与升级问题

### Q: 覆盖安装后问题没有解决

**原因**：可能安装到了不同目录，旧目录的文件仍在使用。

**解决**：
1. 先卸载（开始菜单 → CCB → 卸载）
2. 再重新安装，确认安装目录与之前一致

---

### Q: 朋友/同学安装后遇到 git-bash 错误

最常见原因：安装的是旧版（1.0.6 以下），旧版 ccb.cmd 没有把 Git 路径加入 PATH。

解决：
1. 卸载旧版
2. 安装 1.0.7+

---

### Q: 升级后配置消失了

CCB 升级前会自动备份到：
```
%LOCALAPPDATA%\CCB\backup-before-x.y.z\
```

在这里找回之前的 `settings.json` 等文件，复制回：
```
%LOCALAPPDATA%\CCB\.claude\
```

## 日志与诊断

### 日志文件位置

```
%LOCALAPPDATA%\CCB\logs\
├── launcher-xxxx.log     # 每次启动的启动过程日志
└── debug-xxxx.log        # Claude Code 内部调试日志
```

### 获取详细诊断信息

```
开始菜单 → CCB (Claude Code Best) → CCB 诊断
```

诊断模式启动后窗口不会关闭，可以看到完整的错误信息和日志路径。

### 终端修复工具

如果 Windows Terminal 安装出现问题：
```
开始菜单 → CCB (Claude Code Best) → CCB 终端修复
```
