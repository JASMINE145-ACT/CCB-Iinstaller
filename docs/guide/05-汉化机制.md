# CCB 汉化机制说明

本文介绍 CCB 如何对 Claude Code 进行简体中文汉化，以及汉化的技术实现原理。

---

## 汉化覆盖范围

| 界面位置 | 汉化状态 |
|---------|---------|
| 欢迎界面提示文字 | ✅ |
| 菜单和操作按钮 | ✅ |
| 状态栏文字 | ✅ |
| 错误信息 | ✅ |
| 斜杠命令描述 | ✅ |
| 启动脚本提示（ccb.cmd） | ✅ |
| 安装程序界面（NSIS） | ✅ 简体中文 |
| 安装组件名称 | ✅ |
| API 底层错误（来自服务端） | ❌（服务端返回，无法修改） |

---

## 技术实现：为什么不直接写中文？

Claude Code 的源码编译为 JavaScript bundle，Bun 在 Windows 上运行这些文件时存在一个关键问题：

**Bun on Windows 会把 UTF-8 文件中的中文字符以 Latin-1 方式解析**，导致乱码（mojibake）。

例如，直接写入的 `"快速入门提示"` 会被 Bun 读成 `"å¿«éåº¥å…¥é—¨æé¤"`。

### 解决方案：Unicode 转义

CCB 使用 JavaScript 的 `\uXXXX` 转义形式写入中文：

```javascript
// ❌ 直接写中文（会乱码）
"快速入门提示"

// ✅ Unicode 转义（安全）
"快速入门提示"
```

两者在 JavaScript 运行时的结果完全相同，但文件本身保持纯 ASCII，Bun 可以正确解析。

## 汉化工具链

### patch-i18n.ps1

核心汉化脚本，对 `dist/` 目录下的 chunk 文件做字符串替换：

```powershell
# 对 dist 目录执行汉化补丁
.\scripts\patch-i18n.ps1 -DistDir ".\dist"
```

**工作方式**：
1. 读取每个 `chunk-*.js` 文件（UTF-8 无 BOM）
2. 按原始英文字符串 → 中文 Unicode 转义的映射表批量替换
3. 替换后写回（UTF-8 无 BOM）
4. 验证无 mojibake 残留

### normalize-i18n-literals.mjs

辅助工具，把 JS 文件中已有的字面中文字符转为 `\uXXXX` 格式：

```bash
bun scripts/normalize-i18n-literals.mjs dist/chunk-xxx.js
```

用于处理手动写入了中文字符的情况。

### 提取工具（extract-*.mjs）

一组用于分析 Claude Code 源码结构的脚本：

| 脚本 | 用途 |
|------|------|
| `extract-slash-commands-registry.mjs` | 提取所有斜杠命令的注册信息 |
| `extract-slash-descriptions.mjs` | 提取命令的英文描述文本 |
| `extract-slash-description-literals.mjs` | 提取字符串字面量 |

这些工具在制作汉化映射表时使用，用于确认哪些字符串需要翻译。

## 乱码防护机制

`patch-i18n.ps1` 内置两个验证函数：

### Test-NoMojibake

检查替换后的文件中是否存在乱码特征字节序列：

```
å, æ, è ...（Latin-1 解析 UTF-8 汉字的特征模式）
```

如果检测到，立即抛出错误阻止构建。

### Test-NoLiteralCjkInPatchedChunks

检查 chunk 文件中是否有直接写入的 CJK 字符（而非 `\uXXXX`）：

```
[一-鿿　-〿＀-￯]
```

这确保所有中文都以转义形式存在，消除 Bun 编码问题的风险。

## 斜杠命令汉化

斜杠命令（`/help`、`/memory` 等）的描述文字通过 JSON 映射表管理：

```
scripts/slash-commands-zh-by-name.json   # 按命令名映射的中文描述
scripts/slash-command-descriptions.json  # 完整描述列表
```

示例：
```json
{
  "help": "显示帮助信息",
  "memory": "管理对话记忆",
  "clear": "清空当前对话"
}
```

`apply-slash-command-i18n.mjs` 将这些映射表应用到对应的 chunk 文件。

## 安装器（NSIS）汉化

`installer.nsi` 使用 NSIS 内置的简体中文语言包：

```nsi
!insertmacro MUI_LANGUAGE "SimpChinese"
```

安装界面的按钮（下一步、安装、完成）、进度文字均为中文。

组件名称和描述直接写在 `.nsi` 文件中：

```nsi
Section "Bun 运行时 (必需)" SecBun
    ...
SectionEnd

!insertmacro MUI_DESCRIPTION_TEXT ${SecBun} "启动 CCB 所必需的 Bun JavaScript 运行时。"
```

> `installer.nsi` 需要以 UTF-8 BOM 格式保存，NSIS 才能正确识别中文。

---

## 汉化构建流程

完整的汉化打包步骤：

```
1. 获取原始 Claude Code dist 文件
2. 运行 patch-i18n.ps1 打补丁
3. 验证无乱码（自动）
4. 运行 build.ps1 打包 NSIS 安装程序
   └── NSIS 读 installer.nsi（UTF-8 BOM）
   └── 打包已汉化的 dist/
   └── 输出 CCB-Setup-x.y.z.exe
```

已汉化的 dist 文件直接存储在仓库中，打包时无需重新执行汉化。

---

## 维护汉化

当 Claude Code 发布新版本，需要：

1. 用新版 dist 文件替换 `ccb-installer/dist/`
2. 重新运行 `patch-i18n.ps1`
3. 检查是否有新增的需要翻译的字符串（看 `[miss]` 输出）
4. 在 `patch-i18n.ps1` 中补充新字符串的映射
5. 重新构建安装包
