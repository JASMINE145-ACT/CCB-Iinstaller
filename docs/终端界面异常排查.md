# CCB 终端界面异常排查文档

> **适用范围：** CCB 安装包用户，遇到界面重叠、边框错位、缩放崩溃等问题。
> **前置条件：** 已安装 `CCB-Setup-1.0.1.exe` 或更新版本。
> **最后更新：** 2026-05-27

---

## 一分钟自查

先确认你是否需要继续阅读本文档：

```powershell
# 1. 通过入口脚本启动（不是直接跑 bun.exe）
& "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd" --version

# 2. 看输出是否干净
# 预期：无 "系统找不到指定的驱动器" 错误，输出纯版本号
# 2.1.888 (Claude Code)
```

- **干净无错** → 只说明启动时的驱动器错误已排除；仍需进入交互界面验证排版
- **仍报驱动器错误** → 快转到 [根因 1：驱动器错误](#根因-1驱动器错误)
- **无错但界面叠字** → 继续阅读，走 [根因 2 排查路径](#根因-2tui-渲染异常)

## 问题现象速查表

| 现象 | 最可能原因 | 参考章节 |
|------|-----------|---------|
| 启动顶部：「系统找不到指定的驱动器」 | 系统 Git 探测碰到失效盘符 | [根因 1](#根因-1驱动器错误) |
| 边框断裂 / 右侧多余 `|` 字符 | 终端 ANSI/备用屏 支持不完整 | [根因 2](#根因-2tui-渲染异常) |
| 「你好」叠好几层、同一回复重复出现 | 同上，且无 clearScreen | [根因 2](#根因-2tui-渲染异常) |
| `? for shortcuts` / `* Ruminating...` 位置错乱 | 同上 | [根因 2](#根因-2tui-渲染异常) |
| 缩放窗口后程序直接退出 | CLI 内部 resize 监听触发整屏重绘 | [根因 2 → 缩放崩溃](#缩放崩溃) |
| 以上全部在 VS Code / Cursor 集成终端中正常 | 当前终端宿主兼容性问题 | [终端宿主优先级](#终端宿主优先级) |
| 所有方式都叠字且不缩放也叠 | 可能是 Claude Code 内部渲染问题，需日志 | [收集诊断日志](#收集诊断日志) |

> **与模型无关**：以上所有问题均与 MiniMax 模型（minimax-m2.7）无关，模型只影响回复内容，不影响界面渲染。

> **工作目录不等于安装目录**：界面中显示的 `D:\CCB` 可以只是当前会话打开的项目路径。确认是否使用了新版入口，应检查快捷方式目标或实际执行的 `%LOCALAPPDATA%\Programs\CCB\ccb.cmd`，不能只根据欢迎框中的目录判断。

## 两条独立链路

```text
启动时驱动器错误
    │
    └── 根因 1：启动脚本探测系统 Git 时碰到失效盘符
            已在 ccb.cmd 中修复（禁用系统 Git 探测）
            验证方式：ccb.cmd --version 应无此错误

TUI 界面渲染异常（叠字/边框错位/缩放崩溃）
    │
    └── 根因 2：Windows 控制台 ANSI / 备用屏 / resize 重绘支持不完整
            已在 ccb.cmd 中按终端宿主切换绘制模式并关闭 resize 监听
            但初始渲染仍可能有问题，需交叉验证终端宿主
```

两条链路**互不影响**，可以独立排查。

## 根因 1：驱动器错误

### 确认是否受影响

```powershell
ccb.cmd --version
```

- **无驱动器错误** → 已修复，无需操作
- **仍报「系统找不到指定的驱动器」** → 继续

### 检查启动路径

你是通过什么方式启动 CCB 的？

**情况 A：通过快捷方式启动（如桌面 CCB 图标）**

```powershell
# 查看快捷方式指向的目标
Get-ChildItem "$env:USERPROFILE\Desktop\*.lnk" | Where-Object { $_.Name -like "*CCB*" } | ForEach-Object {
    $sh = New-Object -ComObject WScript.Shell
    $shortcut = $sh.CreateShortcut($_.FullName)
    Write-Host "目标: $($shortcut.TargetPath)"
    Write-Host "参数: $($shortcut.Arguments)"
}
```

如果目标指向 `bun.exe dist\cli.js`（直接跑 bun），说明**快捷方式绕过 ccb.cmd**，没有应用修复。

**情况 B：通过命令行手动启动**

```powershell
cd "$env:LOCALAPPDATA\Programs\CCB"
.\ccb.cmd --version
```

### 修复步骤

1. **重新安装最新版**（确保安装器更新了快捷方式）
   - 下载 `CCB-Setup-1.0.1.exe`
   - 覆盖安装（配置保留在 `%LOCALAPPDATA%\CCB`，不会被覆盖）

2. **确认快捷方式正确**
   ```powershell
   # 删除旧快捷方式（如果存在）
   Remove-Item "$env:USERPROFILE\Desktop\CCB.lnk" -ErrorAction SilentlyContinue

   # 手动重建（如果安装器没有生成新快捷方式）
   $sh = New-Object -ComObject WScript.Shell
   $s = $sh.CreateShortcut("$env:USERPROFILE\Desktop\CCB.lnk")
   $s.TargetPath = "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
   $s.WorkingDirectory = "$env:LOCALAPPDATA\Programs\CCB"
   $s.Save()
   ```

3. **再次验证**
   ```powershell
   .\ccb.cmd --version
   # 应输出：2.1.888 (Claude Code)
   # 无驱动器错误，无其他杂质输出
   ```

### 如果仍报驱动器错误

可能是**配置文件中引用了失效路径**：

```powershell
# 检查配置文件
code $env:LOCALAPPDATA\CCB\.claude\settings.json
```

查找以下内容并删除或修正：
- `ANTHROPIC_API_KEY`：如果包含已暴露的 Key，需在 MiniMax 控制台撤销并重新生成
- MCP 相关路径：引用了已卸载盘符（如 `E:\xxx`）的路径
- `model`：如果配置指向不存在的模型

## 根因 2：TUI 渲染异常

### 终端宿主优先级

不同终端对 ANSI/备用屏/cursor 定位支持程度不同：

| 优先级 | 终端 | 预期表现 |
|--------|------|---------|
| 最推荐 | Cursor / VS Code 集成终端 | 自动使用 fullscreen 备用屏且禁用 resize，用于首选复测 |
| 其次 | Windows Terminal（wt.exe） | 自动使用 fullscreen 备用屏且禁用 resize，用于桌面快捷方式启动 |
| 避免 | 双击 .cmd 打开的传统 CMD 黑框 | 最容易复现叠字 |

### 快速测试：换终端

1. **在 Cursor 集成终端中启动**
   ```powershell
   # 在 Cursor 的集成终端（Term）中执行
   & "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
   ```

2. **在 Windows Terminal 中启动**
   ```powershell
   # 在 Windows Terminal 打开的 PowerShell 标签页中执行
   & "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
   ```

3. **对比观察**
   - 在哪个终端下叠字/错位明显改善？
   - 如果某终端正常而另一终端异常，说明终端宿主会影响复现；CCB 打包渲染器仍是需要兼容处理的一侧

### 交叉验证：终端尺寸与编码

```powershell
# 查看当前终端编码
chcp
# 预期：65001（UTF-8）

# 查看终端尺寸（至少 宽100列 × 高30行）
# 在 CCB 界面出现后，新开一个 PowerShell 窗口执行：
$host.UI.RawUI.WindowSize.Width
$host.UI.RawUI.WindowSize.Height
```

- 窗口过窄（< 80 列）会导致边框算法算错列宽
- 不要边用边缩放窗口（已知会触发 resize 崩溃）

### 环境变量参考

以下环境变量由 `ccb.cmd` 自动处理，无需手动配置（了解即可）：

```bat
REM Windows Terminal 或 VS Code/Cursor 集成终端
set "CLAUDE_CODE_NO_FLICKER=1"           REM 启用备用屏，避免初始 scrollback 增量绘制残留
set "CLAUDE_CODE_DISABLE_VIRTUAL_SCROLL=1"
set "CLAUDE_CODE_DISABLE_MOUSE=1"
set "CLAUDE_CODE_DISABLE_TUI_RESIZE=1"    REM 关闭 resize 监听（防崩溃）

REM 传统 CMD 回退路径会改为：
set "CLAUDE_CODE_NO_FLICKER=0"           REM 不依赖备用屏
```

如需临时强制禁用 fullscreen 进行 A/B 对比：

```powershell
$env:CCB_DISABLE_FULLSCREEN = "1"
& "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
```

如需**临时恢复** resize 监听（仅用于收集日志）：

```powershell
$env:CCB_ENABLE_TUI_RESIZE = "1"
& "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
```

### 缩放崩溃

**现象**：缩放窗口（放大/缩小）后程序直接退出，窗口消失。

**原因**：Claude Code CLI 注册了 `stdout.on("resize", ...)`，窗口变化触发 `fullResetSequence_CAUSES_FLICKER` 整屏重绘，在部分 Windows 终端中导致崩溃。

**已应用的处理**：`ccb.cmd` 已默认设置 `CLAUDE_CODE_DISABLE_TUI_RESIZE=1`，运行中缩放窗口不会触发 CLI 内部重排；在 Windows Terminal 与 VS Code/Cursor 中同时启用 fullscreen 备用屏以规避初始非 fullscreen 增量绘制残留。

**限制**：
- CCB 按启动时的终端宽高完成布局，运行中缩放窗口不再触发实时重排
- 如需改变窗口大小，应先退出 CCB，调整终端尺寸后重新启动

**恢复 resize 监听**（用于复现崩溃收集日志）：
```powershell
$env:CCB_ENABLE_TUI_RESIZE = "1"
& "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
# 现在缩放会触发 CLI 内部 resize 路径 → 可以复现崩溃获取日志
```

## 收集诊断日志

如果按以上所有步骤操作后：
- 仍叠字（且不是缩放触发）
- 或缩放崩溃但想保留错误信息

### 步骤一：用诊断入口启动

对于启动后即出现的叠字，使用 `CCB Diagnostics` 快捷方式（开始菜单 → CCB → CCB Diagnostics）启动。该模式保留 resize 保护，不要缩放窗口。

对于仅在缩放时触发的崩溃，从 PowerShell 显式启用复现模式：

```powershell
& "$env:LOCALAPPDATA\Programs\CCB\ccb-diagnose.cmd" --repro-resize
```

诊断入口行为：
- 通过 Windows Terminal 启动
- 将 Claude Code `--debug-file` 日志写入 `%LOCALAPPDATA%\CCB\logs`
- 启动前检查日志目录能够创建；若目录不可写，会直接提示权限或磁盘问题
- Claude Code 退出后保留窗口，显示退出码和日志路径

### 步骤二：复现问题并保存日志

1. 正常进入界面
2. 只有在使用 `--repro-resize` 启动时，才缩放窗口一次以复现崩溃
3. 退出 CCB
4. 查看窗口中显示的日志路径，例如：
   ```
   [CCB Diagnostics] Debug log: C:\Users\...\CCB\logs\ccb-2026-05-27_...log
   ```

### 步骤三：查看日志

```powershell
code C:\Users\m1774\AppData\Local\CCB\logs\
# 找最新的 .log 文件
```

日志中关注退出码、异常堆栈、终端相关错误和最后一次可见操作。`--debug-file` 是否会包含渲染器内部 `handleResize` / `fullResetSequence` 记录，需以实际日志内容为准，不能预设一定存在。

## 本地隔离复测

日常调试终端布局时，不需要每次安装到另一台电脑，也不建议使用 WSL 验证本问题。WSL 的 PTY、终端环境变量与 Windows 原生启动链不同，不能代表 Windows 安装包中的 TUI 行为。

仓库提供本地隔离部署脚本：

```powershell
cd D:\Projects\claude-code-best
.\ccb-installer\scripts\test-terminal-local.ps1 -PrepareOnly
```

该脚本会将当前工作树部署到：

```text
D:\tmp\ccb-terminal-test\app
```

并使用独立的配置和日志目录：

```text
D:\tmp\ccb-terminal-test\profile\CCB\.claude
D:\tmp\ccb-terminal-test\profile\CCB\logs
```

它不会覆盖正式安装目录、桌面快捷方式或真实 `%LOCALAPPDATA%\CCB` 配置。测试 API Key 如需配置，仅写入上述隔离 `settings.json`。

在 Windows Terminal 或 Cursor 集成终端中分别运行：

```powershell
# 当前默认候选修复：现代终端 fullscreen + resize 防护
.\ccb-installer\scripts\test-terminal-local.ps1 -Mode Modern

# 对照组：关闭 fullscreen，继续保留 resize 防护
.\ccb-installer\scripts\test-terminal-local.ps1 -Mode Flat

# 不缩放时的初始布局问题日志
.\ccb-installer\scripts\test-terminal-local.ps1 -Mode Diagnostics

# 仅用于有意复现缩放崩溃
.\ccb-installer\scripts\test-terminal-local.ps1 -Mode ResizeRepro
```

推荐比较方法：

1. 在 `Modern` 和 `Flat` 中都输入相同的短中文提示，如 `你好` 和 `你可以给我做什么`。
2. 先比较不缩放情况下欢迎框、状态行、输入框和 `medium /effort` 的位置。
3. 只有 `ResizeRepro` 模式允许缩放窗口用于采集崩溃日志。
4. 确定候选策略有效后，再构建安装包进行一次正式安装验证。
