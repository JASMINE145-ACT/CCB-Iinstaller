## 1. 总体说明

本系统目标：**员工 Windows 电脑安装一次后，通过图形界面完成报价、清单核对、Word/Excel 文档处理**；本地价库与业务规则离线可用，组织知识库联网同步。

当前阶段：**首版合并安装包（一个 exe）已基本打通**，正在完成 1.0.1 打包与开箱即用验证；**尚未进入全员试用**。  
以下标准、进度为项目组界定，后续开发、试用、验收均按此执行。

**正式应用起始日：2026 年 7 月 15 日（周三）**

## 2. 稳定性标准

「稳定」指：**在约定环境下，核心功能可重复完成，不因安装/配置/偶发网络导致不可用**。

### 2.1 环境与安装

| 编号 | 标准 | 验收方式 |
|------|------|----------|
| S1 | 新电脑 **仅安装一个 exe**，无需自装 Node/Python/Git | 非技术人员完成安装 ≤15 分钟 |
| S2 | 安装后双击桌面快捷方式即可进入 WanD 界面（含 agents、MCP、价库） | 开始菜单「Check Install」自检全部 OK |
| S3 | 同一版本在 **Windows 10/11 64 位** 上行为一致 | 至少 2 台不同电脑验证 |
| S4 | 程序异常退出后 **可再次启动**，不损坏用户配置 | 连续启动/关闭 10 次无报错 |

### 2.2 运行与可用性

| 编号 | 标准 | 验收方式 |
|------|------|----------|
| S5 | 报价相关 MCP（quotation / accurate）探测 **PASS** | `test-mcp-health.ps1 -Probe` |
| S6 | 单次报价会话 **无未配置 MCP / 无空白 agent 列表** | 人工 + `smoke-wanding-e2e.ps1` |
| S7 | 首条报价消息 **≤3 分钟** 内得到有效回复（含 MCP 冷启动） | 试用期间抽测 5 次，≥4 次达标 |
| S8 | 连续工作 **2 小时** 无崩溃、无卡死需强杀 | 试用人员日报 |
| S9 | 组织知识库：登录后 **24 小时内** 可正常使用侧栏入口 | org 账号 + 重启一次 AionUI |

### 2.3 更新与运维（正式应用后）

| 编号 | 标准 | 说明 |
|------|------|------|
| S10 | 日常小版本 **热更新 zip**（约几十 MB），不全量重装 | 首包上线后启用（见 internal-update §0） |
| S11 | 更新失败 **可回滚**，不影响上一版报价能力 | `internal-upgrade.ps1` 备份 + sha256 |
| S12 | 关键故障 **24 小时内** 有修复包或临时规避方案 | 试用期专人响应 |

**员工更新操作（2026-06-21，热更新通道上线后）：**

- **日常更新**：开始菜单 → **「检查更新 / 版本选择」**（`ccb-wanding-versions.cmd`）→ 选最新版 → 完全退出并重开 WanD。约几十 MB，不全量重装。
- **启动提示**：打开 WanD 时若有新版会弹一次提示框（**不自动安装**），按上面步骤更新即可；不想被打扰可设环境变量 `CCB_NO_UPDATE=1`。
- **（Phase 2 后）** 也可在 **About →「检查更新」** 里同时看到「AionUI」和「万鼎后端」两行，一键更新。
- 更新失败会**自动回滚**到上一版，不影响报价（`internal-upgrade.ps1` 备份 + sha256 校验）。

> 路线与契约：[internal-update](../.trellis/spec/integration/internal-update.md) §3.7 + §6.1；打包入口见 [打包白名单](../.trellis/spec/integration/wanding-packaging-whitelist.md) §6。

**稳定性达标判定：** 试用期末 S1–S9 **全部满足**，且试用期内 **P0 故障（无法报价）= 0 次、P1（功能严重降级）≤2 次且均已修复**。

## 3. 准确性标准

「准确」指：**报价结果与现行价库、业务规则一致，可解释、可复核，关键字段错误率可控**。

**重要说明：** 报价准确度**不是一次性验收即可固化**的指标。价库别名、现场说法、清单习惯会持续变化，**必须依赖业务员在试用与正式使用期间持续反馈**（错匹配、漏项、单价异议、清单识别偏差），开发侧按反馈迭代 agent 规则与价库映射；**无持续反馈则准确度无法保证**。

### 3.1 报价业务

| 编号 | 标准 | 验收方式 |
|------|------|----------|
| A1 | 价库来源固定为打包价库（如 `price_library_cleaned_2026_05_15.xlsx`），不依赖外网 | 离线模式下可完成报价 |
| A2 | **完整设备名称 → 价库匹配**：**匹配正确率 ≥80%** | **4 名业务员**抽测并签字；试用期内**逐单反馈**错例 |
| A3 | **数量、单价、合价、税率** 计算无算术错误 | 自动化 smoke + **4 名业务员**各抽 ≥2 单复核 |
| A4 | 输出 **标准报价单 Excel** 字段完整（项目名、明细、合计、模板格式） | 与「空白标准报价单」模板对照；业务员反馈缺项/错列 |
| A5 | 明显超范围/无价项 **必须提示**，不得静默编造价格 | 4 人各测 ≥1 条无价描述，均应告警或说明 |

### 3.2 清单 / Accurate（**v1 试用范围，与报价并列**）

| 编号 | 标准 | 验收方式 |
|------|------|----------|
| A6 | BOQ 导入后 **行项识别率 ≥85%**（按现行测试样例） | **4 名业务员**各提交 ≥1 份真实清单试跑 |
| A7 | 关键字段（名称、规格、单位、数量）**人工复核错误率 ≤10%** | 4 人复核表 + **逐单反馈**识别偏差 |

### 3.3 组织知识（辅助，不替代价库）

| 编号 | 标准 | 说明 |
|------|------|------|
| A8 | 组织知识 **仅作 SOP/制度引用**，**不得覆盖价库单价** | agent 规则 + 抽测 |
| A9 | 知识库内容与 VPS 同步一致 | 登录 shadow sync 后 spot check |

### 3.4 业务员持续反馈（准确性核心机制）

| 项 | 要求 |
|----|------|
| **参与人数** | **4 名业务员**（与 β/γ 试用名单相同） |
| **反馈内容** | 报价：设备名/规格匹配对错、单价来源、合价算术、模板字段；Accurate：清单行识别、单位数量、漏项/多项 |
| **频率** | β/γ 期间 **每单必记**；每周汇总 1 次错例清单交开发迭代 |
| **闭环** | 开发确认修复或说明规则限制 → 业务员复测 → 记入周报 |
| **正式应用后** | 仍按月收集错例；匹配率、A6/A7 指标**随反馈持续优化**，非一次达标即永久 |

**无业务员持续反馈，不得宣称「准确度已验收完成」。**

**准确性达标判定：** A1–A7 **必须全部满足**；**4 名业务员**试用期末联合签字确认「可用于日常报价辅助」（准确度为当前版本可辅助使用，后续仍依赖 §3.4 持续反馈）。

## 4. 试用安排

### 4.1 试用分期

| 阶段 | 时间 | 范围 | 人数 | 目标 |
|------|------|------|------|------|
| **α 内测** | 6/23 – 6/27 | 安装包、开箱即用、MCP、单条报价 | 开发 + 1 名业务 | 稳定性 S1–S6 过关 |
| **β 小范围试用** | 6/30 – 7/10 | 报价 + **Accurate 清单** + Word/Excel + org 登录 | **4 名业务员** | S7–S9 + A1–A7 |
| **γ 扩大试用** | 7/11 – 7/14 | 真实项目报价与清单（非正式对外盖章） | **同上 4 人** | 持续反馈 + 问题冻结 |
| **正式应用** | **7/15 起** | 印尼/国内指定岗位日常使用 | 按名单 rollout | 达标后纳入正式工具 |

### 4.2 试用支持

- 每人：**安装包 + 简明操作说明（1 页）+ org 账号（如需知识库）**
- **准确性反馈（必做）：** 4 名业务员使用**统一反馈表**记录每单错例（报价匹配 / Accurate 识别 / Excel 字段）；每周例会过一遍，驱动 agent 与价库规则迭代
- 稳定性问题反馈：**统一表格**（现象、截图、日志路径 `%LOCALAPPDATA%\CCB-Wanding\logs\`、优先级）
- 每周：**试用简报**（完成单数、**业务员反馈错例数及闭环**、稳定性统计）

### 4.3 进入正式应用前（退出标准）

1. 第二节稳定性 **S1–S9 全部达标**
2. 第三节准确性 **A1–A7 全部达标**（含 Accurate）
3. **β 阶段 4 名业务员合计至少完成 30 单**（报价 + 清单），无 P0；**每单反馈记录可追溯**
4. **4 名业务员**联合 **书面确认** 可正式使用（准确度为「当前版本可辅助使用」，后续仍依赖持续反馈）

## 6. 当前进展与主要风险

### 6.1 已完成

- 合并安装包架构（AionUI + CCB + 价库 + MCP）
- 开箱即用：启动器 `ccb-launch-aionui.cmd`、安装自检 `ccb-check-install.cmd`、bundled Python（目标机无需系统 Python）
- 自动化验收：`test-mcp-health.ps1`、`smoke-wanding-e2e.ps1`
- 内网热更新方案已设计（首包发出后启用，避免每次 ~850MB 全量重装）

### 6.2 进行中

- **1.0.1 安装包** 打包与装后验证（目标 6/22 前完成）

### 6.3 主要风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 非开发机环境差异（杀毒、权限） | 安装/启动失败 | α 多机验证 + Check Install |
| 报价匹配率未达 80% 或业务员反馈断档 | 准确性不达标或无法迭代 | β 集中调 agent + 价库；**保障 4 人每周反馈**；必要时延 1 周 |
| 组织 VPS/账号未就绪 | 知识库不可用 | 报价主路径不依赖 org；org 作为增强项并行 |
| 首包体积大 | 运维成本高 | 7 月启用热更新 zip，日常只更业务层 |
