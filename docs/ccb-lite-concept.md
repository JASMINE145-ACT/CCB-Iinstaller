# CCB Lite 概念探讨

> 状态：MVP 已落地（`ccb-lite1.0.9.exe`），持续打磨  
> 目标：面向**个人与办公**用户，提供一个专注于日常工作、砍掉开发者命令与噪音的轻量版安装包

## 一句话定位

**CCB Lite = 同一个 CCB 内核 + 办公命令套件 − 开发者命令与入口噪音。**

- ➖ 砍掉开发者命令：`/modo`（TUI 模式选择器）等技术向命令不进 Lite；多模式快捷方式（平铺/安全/文本）、诊断/终端修复、右键菜单、组件选择页一并去除，只留单一入口。
- ➕ 预置办公命令：`/写邮件`、`/总结`、`/会议纪要`、`/翻译`、`/写报告`、`/表格分析`、`/调研简报`、`/协作小组`。
- 🔒 内核不阉割：`dist` 运行时、MCP、Skills、Plugin、Agents/Team 与完整版逐字节相同，专业能力一个不少，只是默认以办公方式呈现。

---

## 背景与动机

当前 CCB 完整版是面向**开发者**的：ripgrep 代码搜索、Git Bash、多启动模式、代码诊断工具、平铺模式……这些功能对开发者价值极大，但对一个需要用 AI 辅助写报告、整理 Excel、做调研的普通职场人来说，既是噪音，也增加了学习成本。

CCB Lite 的核心思路：**去掉一切和「写代码」强绑定的噪音，保留 AI 对日常工作真正有用的能力。**

这里的「轻量」不是能力阉割，而是认知负担降低。`MCP`、`Skills`、`Plugin`、`Agents/Team` 不应被视为开发者专属功能；它们是办公自动化、工具扩展、模板沉淀和多助手协作的基础层，Lite 版必须保留，只是默认用办公用户能理解的方式呈现。

## 目标用户画像

| 典型角色 | 核心诉求 |
|---------|---------|
| 行政/运营 | 起草邮件、整理会议纪要、制作报告 |
| 销售/市场 | 写方案、搜集竞品信息、翻译材料 |
| 财务/数据分析 | 解读 Excel、批量处理表格数据 |
| 产品/设计 | PRD 文档写作、用户调研分析 |
| 管理层 | 快速摘要、决策辅助、文档起草 |

**共同特征：**
- 不懂命令行，不写代码
- 核心场景是文字、表格、搜索
- 期待「双击即用」，不想看到英文报错

## Lite 版核心使用场景

### 场景 1：处理 Excel 数据
```
用户将 Excel 文件拖到 CCB 对话框，或告诉 CCB 文件路径
→ 「帮我统计每个销售员的月度总销量，并找出最高的三位」
→ CCB 通过 Excel MCP 读取文件，分析数据，给出结果
```

### 场景 2：写作与文档
```
「帮我把这段会议录音转写的文字整理成结构清晰的会议纪要，
 格式包括：参与人、决策事项、待办清单」
```

### 场景 3：竞品调研
```
「搜索最近三个月关于[竞品名]的市场动态和用户评价，
 整理成一份简报」
→ CCB 通过 Exa MCP 搜索网络，汇总结果
```

### 场景 4：文件夹内容分析
```
「我有一个文件夹里有 50 份合同 PDF，
 帮我汇总每份合同的甲方、金额和到期日期」
```

## 精简方向

### 1. 安装体验简化

- 去掉组件选择页面（非编码用户不需要选，一键装完）
- 只有一个桌面快捷方式：`CCB`
- 欢迎界面文案面向普通用户（而非「AI 编程助手」）

### 2. 启动体验简化

- 只保留标准模式启动
- 去掉所有 `ccb-flat.cmd`、`ccb-safe.cmd`、`ccb-text.cmd`
- 错误提示更友好：「CCB 无法启动，请检查网络连接或联系管理员」而非技术报错
- **单一入口默认展示「最近对话」**：启动前先列出最近对话（标题/时间/轮数），可一键恢复历史会话或回车开新对话，契合办公用户「跨天继续工作」。无历史时不打断，直接进新对话；设 `CCB_NO_RECENT=1` 关闭。（复用共享脚本 `scripts/ccb-recent.ps1`）
- **日志自动清理**：每次启动仅保留最近 40 个日志，避免 `%LOCALAPPDATA%\CCB-Lite\logs` 无限膨胀。

### 3. 预置办公命令（已落地 1.0.9）

Lite 预置一组面向办公的 slash command，降低上手门槛。开发者命令（如 `/modo` TUI 模式选择器）不进 Lite —— 安装器以 `File /x "modo.md"` 排除，并清理旧版残留的 `modo.md`：

| 命令 | 功能 |
|-----|------|
| `/写邮件` | 根据要点生成正式/非正式邮件 |
| `/总结` | 粘贴长文，输出要点摘要 |
| `/会议纪要` | 把零散记录整理成参与人/决策/待办 |
| `/写报告` | 根据素材生成结构化报告 |
| `/表格分析` | 读取 Excel，回答数据问题 |
| `/翻译` | 中英互译，保持格式 |
| `/调研简报` | 汇总检索结果成简报 |
| `/协作小组` | 多助手协作拆解复杂办公任务 |

### 4. MCP / Skills / Plugin 配置简化

- MCP 扩展层必须保留，Lite 版不能砍掉 MCP 能力
- 默认预装办公高频 MCP：Excel + Exa；后续可扩展 Word、PPT、PDF、浏览器、企业知识库
- Skills 必须保留，用于内置「写邮件」「总结文档」「表格分析」「会议纪要」「调研简报」等可复用办公技能
- Plugin 必须保留，用于安装、更新和管理后续办公插件
- 普通用户默认不看到技术细节；界面文案改为「工具」「技能」「扩展」
- 高级配置入口保留，但默认折叠到设置页或高级菜单里

---

## 不做的事

- **不做 GUI 套壳**：不在 CCB 之上再包一层图形界面，维护成本太高
- **不限制功能**：Lite 只是预置场景不同，Claude 的能力不阉割，用户如需写代码依然可以
- **不做单独更新体系**：跟随完整版的 Claude Code 版本升级节奏

## 实现路径

### 方案 A：独立安装包（推荐）

新建 `installer-lite.nsi`，基于 `installer.nsi` 裁剪：
- 短期保留 ripgrep 作为隐藏依赖，避免影响文件/资料检索；后续确认无影响再物理裁剪
- 去掉 SecDeskModes、SecContext
- 简化开始菜单
- 替换 DESCRIPTION 和欢迎文案
- 内置 Lite 专属 slash commands

**优点：** 独立维护，互不影响  
**缺点：** 需要单独维护一份 NSI

### 方案 B：安装时选择 Profile

在现有 installer 中增加「用途选择」页：
```
[•] 开发者模式（完整版）
[ ] 职场助手模式（Lite）
```
根据选择决定安装哪些组件和快捷方式。

**优点：** 一个安装包覆盖所有人  
**缺点：** 安装逻辑更复杂，测试面加倍

### 方案 C：安装后通过配置文件切换

安装完整版，但通过 `ccb-profile.json` 控制显示哪些功能、预置哪些 Prompt。

**优点：** 零额外维护成本  
**缺点：** 安装包体积不会减小；对用户体验改善有限

## 推荐决策

> **短期：方案 A（独立安装包）—— 已落地 `ccb-lite1.0.9.exe`**

5. ✅ 输出 `ccb-lite1.0.9.exe`（与完整版同核心版本号），可发给非技术用户试用
6. ⏳ 收集反馈，再决定是否合并为方案 B

## Slash Command 裁剪方案

当前共 ~100 个命令，非编码用户实际用得上的不超过 20 个。

**两类命令必须分开看：**

- **办公 `.md` 自定义命令**（`resources/commands/*.md`）：按安装器分发，**已实现 Lite 专属** —— Lite 只发 8 个办公命令并以 `File /x "modo.md"` 排除开发者 `/modo`，完整版只发 `/modo`。这是当前真正落地的「Lite 砍命令」。
- **内置 slash 命令（~100 个）**：内嵌在共用的 `dist` 里。完整版与 Lite **逐字节共用同一份 `dist`**（见 `ccb-lite-relationship.md`），因此「只在 Lite 隐藏这 ~80 个」无法靠改 `dist` 实现（会同时影响完整版）。可行路径有二：
  1. **配置级隐藏（推荐，纯 Lite 专属）**：若 Claude Code 支持按 `settings.json` 隐藏/禁用命令，则由 `ensure-mcp-settings.ps1` 仅写入 Lite 配置目录，零 `dist` 改动、不影响完整版。**实现前需先确认核心是否支持该配置项。**
  2. **共用裁剪（两版同时生效）**：改 `slash-commands-zh-by-name.json` + `patch-i18n.ps1` 的自动补全列表 —— 作用于共用 `dist`，完整版也会一起裁掉，需评估是否可接受。

下表是内置命令的裁剪候选清单，落地前请先在上面两条路径里选定方案。
