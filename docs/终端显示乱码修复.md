# CCB 终端显示乱码修复

这份文档只处理“界面能打开、能运行，但显示异常”的问题。

如果窗口全黑、没有欢迎语、没有输入框、没有报错文字，优先看：

- [终端界面异常排查.md](./终端界面异常排查.md)

黑屏通常是启动链路、TUI 重绘、运行时文件、Git Bash 或杀软拦截问题，不等同于字体乱码。

## 先判断是哪种问题

| 现象 | 更可能的原因 | 处理方向 |
| --- | --- | --- |
| 中文变成问号、方块、乱码 | 终端编码或字体问题 | 看本文 |
| 边框线、图标、符号变成方块 | 字体不支持 Unicode / Powerline 字符 | 换字体 |
| 窗口全黑，什么都没有 | TUI 没重画、进程卡住或秒退 | 看“终端界面异常排查” |
| 双击后窗口一闪而过 | 启动失败、文件缺失、被杀软隔离 | 跑诊断脚本 |
| `/mcp` 看不到 exa / excel-mcp | MCP 配置路径问题 | 看 `好用MCP/00_CCB打包MCP正确路径.md` |

## CCB 里已经做过的兼容处理

新版 `ccb.cmd` 启动时已经做了这些事：

```bat
chcp 65001
set CLAUDE_CODE_DISABLE_VIRTUAL_SCROLL=1
set CLAUDE_CODE_DISABLE_MOUSE=1
set CLAUDE_CODE_DISABLE_TUI_RESIZE=1
```

这些设置用于减少 Windows 终端里的中文布局、滚动、鼠标和 resize 重绘问题。

所以用户侧优先检查终端和字体，不要先去改程序代码。

## 方案一：使用 Windows Terminal

推荐用 Windows Terminal 跑 CCB，因为它对 UTF-8、中文、Unicode 边框线的支持比老 CMD 更稳定。

CCB 1.0.6 起，安装器会默认尝试处理终端环境：

1. 如果缺 Windows Terminal，且电脑可用 `winget`，安装器会尝试安装 Microsoft Windows Terminal。
2. 如果公司策略、网络或应用商店限制导致安装失败，CCB 本体仍会继续安装。
3. 安装最后会自动执行一次终端快捷方式修复。

正常情况下，用户安装完只需要双击桌面的：

```text
CCB
```

如果仍然黑屏或界面不重画，再双击桌面的：

```text
CCB Flat Mode
```

如果桌面没有出现这些快捷方式，或者用户后来安装了 Windows Terminal，可以手动运行开始菜单里的：

```text
CCB (Claude Code Best) -> CCB Terminal Fix
```

这个工具会检测 Windows Terminal，并重新创建快捷方式：

```text
CCB
CCB Flat Mode
```

优先用 `CCB`。如果仍然黑屏或界面不重画，再用 `CCB Flat Mode`。

检查是否安装：

```powershell
wt.exe --version
```

如果已经安装，可以直接运行：

```powershell
& "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd"
```

如果没有安装，可以从 Microsoft Store 安装 Windows Terminal，或者在允许 `winget` 的机器上运行：

```powershell
winget install Microsoft.WindowsTerminal --accept-package-agreements
```

公司电脑如果禁止安装 Windows Terminal，就继续看后面的字体和 Flat 模式。

## 方案二：更换终端字体

很多“乱码”其实不是编码错，而是字体不支持 Claude Code TUI 用到的边框线、图标或 Powerline 字符。

推荐字体：

| 字体 | 建议 |
| --- | --- |
| Cascadia Code PL | 首选，适合 Windows Terminal |
| Cascadia Mono PL | 更窄一些，也稳定 |
| JetBrains Mono | 通用、清晰 |
| Nerd Font 系列 | 图标支持最完整 |

Windows Terminal 设置方法：

1. 打开 Windows Terminal。
2. 按 `Ctrl + ,` 打开设置。
3. 选择当前 Profile。
4. 进入“外观”。
5. 字体改成 `Cascadia Code PL` 或 `JetBrains Mono`。

VS Code / Cursor 集成终端可以在 `settings.json` 里加：

```json
{
  "terminal.integrated.fontFamily": "Cascadia Code PL, JetBrains Mono, Consolas",
  "terminal.integrated.fontSize": 13
}
```

## 方案三：使用 Flat 模式对比

如果怀疑是全屏 TUI 或备用屏绘制异常，可以用本地测试脚本对比 Modern / Flat 两种模式。

在开发机上运行：

```powershell
cd D:\Projects\claude-code-best\ccb-installer
.\scripts\test-terminal-local.ps1 -PrepareOnly -SandboxRoot D:\tmp\ccb-terminal-test
.\scripts\test-terminal-local.ps1 -Mode Modern -SandboxRoot D:\tmp\ccb-terminal-test
```

再开一个测试：

```powershell
.\scripts\test-terminal-local.ps1 -Mode Flat -SandboxRoot D:\tmp\ccb-terminal-test
```

判断方式：

| 测试结果 | 说明 |
| --- | --- |
| Modern 正常，Flat 正常 | 终端环境基本没问题 |
| Modern 异常，Flat 正常 | 多半是全屏/备用屏/TUI 重绘兼容问题 |
| Modern 异常，Flat 也异常 | 多半是字体、编码或运行时问题 |
| 两个都黑屏 | 不按本文处理，去看启动异常排查 |

## 方案四：开启系统 UTF-8 支持

只有在中文仍然显示异常时才考虑这一步。

操作路径：

1. 按 `Win + R`。
2. 输入 `intl.cpl`。
3. 打开“管理”。
4. 点击“更改系统区域设置”。
5. 勾选“Beta: 使用 Unicode UTF-8 提供全球语言支持”。
6. 重启电脑。

注意：这会影响系统区域设置。公司电脑可能被策略禁止，不要把它作为第一方案。

## 方案五：绕过 TUI，用纯文本模式

如果公司电脑终端限制很重，TUI 怎么调都显示不正常，可以临时用 `-p` 纯文本模式。

单次提问：

```powershell
echo "你好" | & "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd" -p
```

直接进入 print 模式：

```powershell
& "$env:LOCALAPPDATA\Programs\CCB\ccb.cmd" -p
```

这种方式没有 TUI 边框和全屏绘制，显示更朴素，但能绕过大部分终端渲染问题。

## 朋友电脑上的建议排查顺序

按这个顺序走：

1. 先确认不是黑屏。如果是黑屏，看 `终端界面异常排查.md`。
2. 用 Windows Terminal 启动 CCB。
3. 把字体改成 `Cascadia Code PL`。
4. 如果仍异常，用 Flat 模式对比。
5. 只有中文仍乱码时，再考虑系统 UTF-8 设置。
6. 公司策略限制太多时，用 `-p` 纯文本模式兜底。

## 正常显示应该是什么样

正常时应该能看到：

- 中文欢迎语正常。
- 输入框正常显示。
- 边框线不断裂。
- 图标不是方块。
- 切换模型、打开 `/mcp`、输入中文都不会破版。

轻微的边框差异不影响使用。真正需要处理的是中文不可读、输入框错位、界面全黑、启动失败。
